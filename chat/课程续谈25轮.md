# 课程续谈 25 轮｜AI 时代下的搜索技术——以 RAG 为例

这份记录保留学生代理（AI 模拟）与研究助手（AI）实际互发的 25 轮正式发言，每轮一问一答。学生代理参考《搜索技术演变史_完整对话.md》里的真实用户提问。第 01 轮的引文来自该记录第 02 轮。引文以外的学生代理发言均由 AI 生成。讨论、实现和修订并行，第 01–15 轮讨论设计，第 16–25 轮复核实跑结果。另见[课程实验报告](../课程报告.md)。

## 第01轮

**第01轮｜学生代理（AI 模拟）**

真实学习记录第 02 轮原问是：
> RAG这个技术是如今AI时代机器搜索使用的最优解方案吗？为什么选择了这个技术

我想把「最优」问得具体一些。搜索技术从目录和网页链接走到现在，什么时候给我一个链接就够了，什么时候该给直接答案，什么时候该继续搜？能不能用同一批软件文档举例？

**第01轮｜研究助手（AI）**

把成功条件跟用户动作对应起来。用户问「Aster 官方配置指南在哪」，成功是给出正确入口，链接即可。问「Aster 当前的默认重试次数是多少」，一段现行官方文档足够时，可以直接给值和出处。若问「Aster 与 Boreal 的当前默认超时各是多少」，第一批只找到 Aster 的值，缺失的是 Boreal 的指定字段，应针对它补搜并再次检查版本和出处。若封闭语料没有第二个值，可把已找到的来源和缺口说清楚，但不能凭已有片段完成比较。这样原来的「最优」就变成同一语料下针对不同任务的证据、成本和交付选择。

## 第02轮

**第02轮｜学生代理（AI 模拟）**

所以我理解是，目录、倒排索引和 BM25 主要解决怎么找到东西，RAG 决定怎么把找到的东西放进答案，Agent 决定该不该换条路再找。这个理解哪里不准确？咱们实验要测的是哪一层？

**第02轮｜研究助手（AI）**

目录用人工或结构化分类组织入口，倒排索引记录词项到文档的映射，BM25 是利用词频和文档长度等信号排序的打分函数。它们可以共同出现在同一检索系统里。RAG 将外部检索证据引入生成环节，有的系统一轮取片段，有的也会改写查询或多轮搜。Agentic Search 还可能有显式任务状态、工具选择与重复决策，采用固定缺口规则不等于实现自主 Agent。本实验共享词法排序、已解析任务和固定模板，比较第一轮候选如何按用途交付，以及证据缺失或版本不符时是否追加检索。它隔离了搜索之后、开放式生成之前的证据控制。

## 第03轮

**第03轮｜学生代理（AI 模拟）**

那为了比较，我用同一句话问「Aster 的默认超时是什么」，直接给文档链接和给出一个数，它们都可能对。为什么不能拿一个准确率就排第一？你会怎么把找入口、找值、比较和封闭语料找不到这几种题分开？

**第03轮｜研究助手（AI）**

链接和答案解决的事情不同，混成一种准确率会偷偷指定谁负责读文档。导航题给正确官方入口，按入口是否位列前三等排名指标评价。单值题给目标字段值和支持它的现行出处。比较题要两个实体的值及各自独立证据，不能把找到一边当比较完成。不可答题的请求形式仍可单值或比较，不过金标认定封闭语料缺关键证据，应统计是否拒绝不受支持的完整回答。链接列表可同列报告是否覆盖所需证据组，具体值与出处是否正确则只对交付答案的方法算。用同一批问题允许查不同交付所需的代价，最终选择取决于目的。

## 第04轮

**第04轮｜学生代理（AI 模拟）**

Agentic Search 用的是什么技术呢？如果我问比较两款软件，你这个原型怎么知道该补搜哪一款、哪一个字段？说一个实际工作步骤，再告诉我哪些判断已经由实验数据替它做好了。

**第04轮｜研究助手（AI）**

完整 Agentic Search 可能用模型拆解任务、做查询改写和工具选择，在检索后按状态决定继续或停止。原型先把问题解析成必需的 `(对象,字段)` 清单。例如比较 Aster 与 Boreal 的超时就是两个槽。共享 BM25 候选先走证据门槛，若仅 Aster 槽通过，则生成带 Boreal 对象和超时字段的定向查询，再验新候选。照此流程，只需要规则也可以做一次最小的补搜决策。槽的对象、字段，浏览还是作答的交付意图，以及当前文档目录的可信状态均由实验预设或共享供应。原型没有评估开放式 Agent 能否从用户自然语言正确推导这些判断。

## 第05轮

**第05轮｜学生代理（AI 模拟）**

如果前 3 条里 Aster 有官方文档，Boreal 有一条看起来很像的镜像，那算两边都搜到了吗？给一条具体反例，说明什么证据才算填满一个槽，为什么相关度高不能替代这个判断。

**第05轮｜研究助手（AI）**

假设 Boreal 官方现行 `timeout` 是 `45 s`，镜像转录旧版的 `60 s`，却反复出现与问句高度重合的「Boreal current default timeout」。BM25 高分反映词法匹配，不能替镜像证明版本或来源。这个槽要同时满足片段明确指向 Boreal、字段确实是 `timeout`、来源在官方域清单上、片段版本与可信清单中的现行版本相符。Boreal 的现行 `retry` 也不是同一字段。即使镜像碰巧抄对数值，本次任务的「可追溯到现行官方材料」契约仍未完成。

## 第06轮

**第06轮｜学生代理（AI 模拟）**

如果镜像比官方原文写得更清楚，甚至内容一模一样，也要拒绝吗？我想知道这是一条通用检索规则，还是因为我们题目明确问「官方现行默认值」。这个条件怎么控制，才不会把一个业务选择说成 RAG 本身的能力？

**第06轮｜研究助手（AI）**

这是任务约束，不是普适排序规则。问「哪个教程好懂」可以接受镜像、社区经验和独立评测，注明来源即可；问「官方现行默认值」则需要现行官方材料能核实。实验把两视图用同批问题配对，一份只有官方当前文档，一份再加官方旧版与镜像，同时让所有回答方法面对同一成功契约。无门槛对照的目的正是展示不执行该业务约束会发生什么。镜像复制得一点不差时，可扩展成辅助解释或跳回原出处的线索；如允许镜像独立担保，就必须先定义如何验证它等价，不能事后改评判规则。

## 第07轮

**第07轮｜学生代理（AI 模拟）**

我还是有个疑问：系统知道「Boreal.timeout」，也知道谁是现行版，那不是直接查结构化记录更简单吗？我们是不是把最难的问题偷偷给了答案？请明确哪个数据是所有方法共同可见、哪个只给评分，再说为什么要有「从一开始逐槽定向」的对照。

**第07轮｜研究助手（AI）**

给策略看题面、解析后的必需对象字段及来源版本清单。它们仍需从语料找到携带值的证据。正确答案、金标证据 ID 与哪些题真实缺证据只在评分侧，不能传给检索或门控。已知结构化槽确实跳过了自然语言解析。若另有可信配置表直接保存 `(产品, 版本, 字段)→值`，应先测直接查表。这个语料只给文档片段，因此用逐槽全定向作强对照，同样确认来源和版本，但跳过泛搜。它可以检验初次宽松搜索在发现证据时是否有复用价值，也可能发现某些题先针对性找更节省。

## 第08轮

**第08轮｜学生代理（AI 模拟）**

要是我问「Aster 和 Boreal 怎么配」，连是比较超时还是重试都看不出来，这个流程应该先找、先问还是直接答？我想用一个失败例子提醒自己，实验把意图、对象和字段都给定后，结论具体少覆盖了什么。

**第08轮｜研究助手（AI）**

「怎么配」可能问默认值、配置文件位置或面向故障恢复的建议。若字段不同会实质改变结果，先询问要比较超时、重试还是部署步骤。也可先给两份官方配置入口，并说明待明确的比较维度。反例是系统误把「怎么配」解析成 `timeout`，官方新文档和读数都正确，却没解决用户关心的重试。证据门槛只能检查是否支持已给定槽，无法发现槽本身错了。本次不能评价意图分类、实体链接、字段消歧，以及会话中何时澄清。

## 第09轮

**第09轮｜学生代理（AI 模拟）**

那是不是把 top-k 放大一些，很多缺口就自然没了？我们拿一次宽窗对比多次窄搜，容易一边给七段、另一边最多给九段。怎么做对照才看得出是「换查询方向」有用，而不是多拿了几个片段？要是预算没完全拉齐，报告该怎么说？

**第09轮｜研究助手（AI）**

窗加宽确实能救回一部分被截断的证据，所以宽窗门控是必要基线。若要隔离查询方向，可保持同一证据门槛和同一总片段上限，再比较泛查一次、把新增额度耗在泛查后续候选、把它分给缺口查询。也可按逻辑调用上限画覆盖与成本曲线。主试验若比较宽窗七段与缺口策略最多九段，就还混入候选预算、排序范围和调用数，不该把全部准确差归于改写查询。可精确说在已测配置下各自得到多少正确并支付多少代价。对个别案例再核对定向查找回的证据在原全局排序的位置，才能解释它具体怎样超越宽窗。

## 第10轮

**第10轮｜学生代理（AI 模拟）**

同一题先泛搜一次，再分别补 Aster 和 Boreal，最多三次；一开始分别搜只要两次。是不是说缺口策略只有在首轮常凑齐两边时，才可能少调用？有没有一条不用看答案、单看首轮证据槽就能验算节省条件的式子？

**第10轮｜研究助手（AI）**

令 `s` 为题目需要的槽数，`h` 为首批已有唯一合格证据的槽数。若每个未填槽都补一次，且无冲突提前退的分支，则缺口方案用 `1+s−h` 次，全定向用 `s` 次，差值为 `1−h`。对双槽题，首轮齐两槽少 1 次，齐一槽持平，零槽就多 1 次。因此在比较子集的期望上，节省条件是 `E[h]>1`，等价于「齐两槽的比例大于零槽比例」，不需要看答案，只需核对门控判定过的槽。单槽题中 `h≤1`，按该计数缺口方案不可能严格少调用。若首轮冲突导致不补该槽，公式须改用实际补查次数，并单列因此放弃的题。

## 第11轮

**第11轮｜学生代理（AI 模拟）**

我看过很多 AI 搜索答案，末尾有好几个链接，却不清楚哪一个支持哪句话。咱们会不会把「有链接」当成「有证据」？尤其两个现行官方片段互相冲突，和只有一边找到，这两种情况系统应该怎样停下来？

**第11轮｜研究助手（AI）**

给出处时应把每个数直接配到自己的证据片段 ID，不能靠末尾一串网址担保整段。比较题两槽齐全才可交付完整对比。只有一边找到时，规则允许对另一槽补查一次，仍缺就在测试中返回证据不足。两条现行官方片段进入同一检查窗口却给出不同值时，`select` 检出冲突并拒绝这次完整回答，日志将其与普通缺槽区分。原型不证明窗口之外没有冲突。实际界面若展示已核实一边，应明确另一边未知，并保留每个已核实值的引用，不把局部结果计成完整比较。

## 第12轮

**第12轮｜学生代理（AI 模拟）**

证据不足是不是就能说「这个配置没有」？一边是合成语料故意没放官方值，一边是值有、但 top 3 找漏了。它们在输出里看起来一样，你怎么区分合理拒答和漏答，又怎么防止它靠全拒答拿第一？

**第12轮｜研究助手（AI）**

运行时说「在本次搜索范围内没有核实到足够证据」，无法从未命中推断配置不存在。在评分时才用独立金标分开：权威语料有完整证据但拒绝是可答未覆盖，缺任何必要证据而拒绝是合理拒答。对答案方法用同一请求分母报告四个互斥结果：金标证据支持作答、完整作答但不符合金标、可答未覆盖、合理拒答。并单列可答题正确覆盖 `grounded/N_answerable`。全拒绝策略即使零错答，其可答覆盖仍是零，读者可直接看出代价。对链接列表用来源覆盖口径，没金标的查询不把没有列出官方链接当成额外失败。

## 第13轮

**第13轮｜学生代理（AI 模拟）**

金标目前是指定的片段 ID。如果两个现行版本的官方页面都写同一个正确值，引用另一个官方来源也会被判错吗？为什么在合成数据里可以这样打分，人工评审真实搜索答案得怎么改？

**第13轮｜研究助手（AI）**

会。程序要求答案引用与指定槽的金标片段 ID 一致。主语料为每个可答槽只生成一项官方现行证据，因此单 ID 可以还原这次契约，不会在主样本里误罚另一个等价官方出处。真实资料常有发行说明、帮助文档和 API 参考并存，需要每槽标出可接受的证据集。以引文能支持同实体、版本、适用范围及数值为准，并把出处是否可核验与值是否正确分开。两份文档若分别面向免费版和企业版，即使都是官方现行，也要消歧而非自动视为等价。

## 第14轮

**第14轮｜学生代理（AI 模拟）**

那这次旧版和镜像是刻意放进来的。它们怎么生成，为什么比现行资料更容易排前？这算现实网页的代表，还是你人为构造的压力测试？我想把能控制的变量和以后才能知道的真实比例分开。

**第14轮｜研究助手（AI）**

官方现行片段在几种同义短语中选择其一，例如只写 `file export allowance`。构造旧版和镜像时，字段描述常同时写 `export quota file limit allowance`，并在不同记录放入同主题词。长短不会保证谁排第一，但在查询跨同义词时，干扰项与词法得分更容易竞争。旧版标为官方 v1，镜像即便写 v2，发布者也不同。两套视图共用同一 36 种软件、同一批题与金标，只在混合视图新增干扰；增加干扰同时改变 IDF 和平均长度，所以它测整个视图变化的作用，不能把差异单归于某个打分变量。它是受控压力测试。真实网页的混杂率、页面长度、元数据准确性以及查询分布需另采样。

## 第15轮

**第15轮｜学生代理（AI 模拟）**

怎么算这个实验没白做？我想先写下，哪条对照验门控，哪条验定向补搜，哪条可能直接推翻「先泛搜更省」。再给三条代码检查：什么结果出来要先查程序，什么结果虽然不漂亮也该原样写？讨论和实现是并行的，别写成事前预注册。

**第15轮｜研究助手（AI）**

固定 Top-3 与同窗门控共享候选，最直接检验证据门槛。比较宽窗与同窗，观察多拿全局候选的收益；比较缺口补搜与宽窗、同窗，报告配置下的额外正确数及调用和片段成本，预算没对齐就不作纯查询方向的因果解释。全定向是优先挑战「先泛搜更省」的对照。校验可做三条：各策略同题同视图可配对且各结果类别计数和等于该分母；导航走同一 Top-3，六法逐题链接一致；手工例应能重现旧版误交付、定向补回和现行版本清单错时失守。若结果出现一开始定向更省、宽窗也救回很多、门控正确但漏答，均原样报告。设计讨论与实现并行调整，不能称预注册。

## 第16轮

**第16轮｜学生代理（AI 模拟）**

来看实跑。`run.json` 的小例子里，Aster 旧条目写 15 files，新版写 25，Birch 写 30。既然首批已经看到了两个产品，为什么固定窗口会答错，门控却没答？缺口补搜到底补了谁，最后用了几个引用和几次调用？

**第16轮｜研究助手（AI）**

固定例的首批是 Aster v1 的 `15 files` 和 Birch v2 的 `30 files`。固定窗口能识别两个对象与字段，但不验发布者和现行版本，于是完整交付了带 Aster 旧出处的比较，计错答。门控认可 Birch v2，Aster v1 版本不符，因此两槽未齐，计可答未覆盖。缺口策略复用首批的 Birch 证据，只向 Aster 增发一次定向配额查询，找到 v2 的 `25 files`。最后返回 `25` 和 `30` 两个值、各一条引用 `aster-new` 与 `birch-new`，总计两次逻辑检索。这个例子的首批由程序直接给定，用来核对分支，主语料用 BM25 生成候选。

## 第17轮

**第17轮｜学生代理（AI 模拟）**

混合组的 Top-3 链接覆盖是 66/90，怎么不是 66/102？同样三条链接，找入口是 36/36，单值 25/36，比较只有 5/18。请分开解释这三项。如果拿 66 和定向策略答对的 54 直接比大小，会错在哪里？

**第17轮｜研究助手（AI）**
