# 续讨论 25 轮｜水下无线光通信资料的 BER 证据配对

这份 Markdown 记录「学生代理（AI 模拟）」和「研究助手（AI）」实际互发的 25 轮正式发言，每轮一问一答。学生代理参考《搜索技术与RAG_对话整理.md》中七个真实用户问题的推进方式。第 01 轮的引文来自该文档第 7 节，其余学生代理发言由 AI 生成。讨论、实现与实验修订并行。第 01–15 轮聚焦设计，第 16–25 轮复核已运行的数据。

## 第01轮

**第01轮｜学生代理（AI 模拟）**

早期讨论最后的真实用户原问（《搜索技术与RAG_对话整理.md》第 7 节）是：
> AI 真的可以发现新知识吗？意思是你可以通过 RAG 技术搜索已有知识，最后自己创建新的知识吗？

我想先把这个问题变小一点。假如我们用 RAG 查水下无线光通信（UWOC）论文里某次实验的误码率（BER），连 BER 是在哪个条件下测的都可能配错。能不能先用这个例子看看，从搜到资料到有证据地回答，中间到底差了哪一步？

**第01轮｜研究助手（AI）**

中间差的是验证「这个值属于题目指定的那次实验」。早期讨论第 7 节区分了知识重组、候选假设和经验证的科学发现。我们先做知识重组之前的证据配对。比如同篇文献分别报告「10 m、OOK」和「15 m、OFDM」。BER 段落若只写「该系统在测试中达到某误码率」，搜到同一篇文章也无法决定它来自哪一行。可先固定条件锚点，再要求 BER 的原始行能支持同一次实验，只有配齐身份和出处才交付数值。如果验证缺少归属，就继续找该行或拒答。本实验即使成功，也只能证明一种证据获取方法在受控条件下更可靠，不能说明新发现了水下通信规律。

## 第02轮

**第02轮｜学生代理（AI 模拟）**

所以我理解是，论文搜对了也可能把数值拿错？能不能给一条具体的问句、同一篇论文里两条可能命中的记录，再写出一个「每个数字都是真的，合起来却错了」的答案？我也想知道，最后以什么东西为准判它错。

**第02轮｜研究助手（AI）**

用一个合成例子。问「合成记录 P 中，10 m、OOK 的这次试验报告了多少 BER？」源表第 4 行是 `10 m，OOK，BER=2×10⁻⁴`，第 9 行是 `15 m，OFDM，BER=8×10⁻⁵`。BER 片段切出来后可能只留下「所测 BER 为 8×10⁻⁵」，于是回答「10 m、OOK 的 BER 是 8×10⁻⁵」。句中的条件与数值都存在，但没有哪一行支持它们的组合。金标准是指定条件锚点对应的真实源行及其 BER 记录身份。即使第 4、9 行碰巧给出同一数值，引用了错误行仍是归属错误。反过来，正确源行但数值被 OCR 抄错是数值抽取错误，应另行测量。

## 第03轮

**第03轮｜学生代理（AI 模拟）**

那这种问题，RAG 是最合适的吗？如果论文原来就是一张完整的实验表，我直接按论文、距离和调制去查不就行了？请说说什么时候值得走检索片段这条路，什么时候应该直接用结构化表。

**第03轮｜研究助手（AI）**

一张可靠的机器可读源表若同时含条件与 BER，且键足够唯一，直接用 SQL 或表查询更简单。距离和调制可能不足以区分重复试验，所以最好有作者的实验编号或稳定的源行键。RAG 的价值出现在材料散落于正文、表格、图注与附录，需要先将自然语言问题定位到候选段落时。这里刻意模拟切块后只保留部分上下文的情况，把锚点定位视为已完成，再测如何验候选的归属。独立源表在程序里只给来源行与实验 ID 的对应关系。若实际系统已能直接从同一源查全量条件和 BER，先测直接查表即可，检索片段可以用于附带解释和开放式问答。

## 第04轮

**第04轮｜学生代理（AI 模拟）**

Agentic Search 可以换工具、再搜一次。这里为什么不用 Agent 自己判断？你说的按键补查具体用了什么信息？如果正确 BER 根本没进 top-k，补查能解决；如果候选里已经有一个看起来对的键，但其实接错了，流程还会往下查吗？

**第04轮｜研究助手（AI）**

用规则先做一个可核对的证据充分性判断：条件已知 `(paper_id, run_id)`，同篇 BM25 的 top-k 没有相同键时，才调用这个复合键的补查接口。补查可能找回落在排名下方但键仍存在的片段。若 top-k 已有同键，单纯按键方案就会停；键错挂时，这正是错误会漏过的位置。加源行校验的方案对任何拟提交候选都要验证，无论它来自 top-k 还是补查。源行归到别的 run 时，至少拒绝提交这条候选。这样可检验 Agent 的「证据够了吗」能否落成明确动作，再讨论是否让模型负责选择下一种工具。

## 第05轮

**第05轮｜学生代理（AI 模拟）**

复合键自己会错，那到源表再查一次就一定有用吗？我有点担心两边都是同一个 PDF 解析器产的，错也一起错。这里所谓「独立」到底是独立得到的哪几个字段？请顺便告诉我这张验证表能看见 BER 数值吗。

**第05轮｜研究助手（AI）**

独立需要落实到出处识别链路。合成数据把当前候选的索引键与原始源行的归属分开。扰动索引侧 `run_id` 时，验证表仍把同篇的 `source_row_id` 映射到原来的 run。它在校验时提供归属，不提供 BER 数值，因而不能替代检索或证明候选片段的数字抄对了。现实中，可让索引键来自自动段落抽取，让归属证据来自出版社补充表、人工核过的原始行或采用独立规则的解析路径。若两路都继承同一错误关系，查两次可能错误地自洽。应分别注入索引坏标和共因错误，才能看到保障条件。

## 第06轮

**第06轮｜学生代理（AI 模拟）**

所以补查有点像定向找缺的东西，不是再做一遍相似度搜索。我想拆开比较到底是排名、补查还是源行复核在起作用。除了独立取 top-1，为什么还要做「top-k 内连接」和「全拉后连接」？它们各卡住哪个问题？

**第06轮｜研究助手（AI）**

五种方式可以逐步定位收益。BM25 同篇 top-1 只看检索相关性。top-k 内连接若能减少错配，说明对实验身份的约束有价值，但正确候选可能被 k 截掉。top-k 加键补查与它共享首批候选，二者的正确覆盖差异刻画补查收益。全拉同篇再连接尽量消除 k 截断，对照同一套索引标签下的召回与读取代价，但错标仍可使它连错。最后将同样的补查加源行复核，比较它阻断的错配和新增的拒答，并单独报告源表读取次数。全拉或补查如果有多个候选共用同键，需先约定确定的选取或显式拒答规则，避免把排序细节带来的差异误称为校验收益。

## 第07轮

**第07轮｜学生代理（AI 模拟）**

全拉明明拿到了最多的片段，按键补查怎么可能比它更好？如果干净键下两者正确率不同，我要先怀疑实现；如果错误键下有多个候选，那谁先被选中可能也影响结果。能不能先说清我们用什么规则，再给一个会使复核拒答、却还有别的方法能救回的反例？

**第07轮｜研究助手（AI）**

在同一可读语料与键索引上，干净且唯一的键让全拉与按键补查拿到同一候选，两者的主要差别应是读取量。若同键不唯一，需写明实现如何稳定选择，例如先保留最高 BM25 的同键项，分数相同按唯一片段 ID，或直接拒绝歧义。一个反例是源行 r1 为正确实验 1 的 BER，r2 属于实验 2，但误贴实验 1 的标签。若 r2 排在 r1 前面，先择再验会拒答，即使 r1 仍可取得。逐个检查全部候选的源行可以救回 r1，代价是更多验证读和唯一性检查。若键互换而正确 r1 被标到实验 2，枚举实验 1 的键仍救不回，需要独立源表提供反向 `(paper, run)→row` 能力，或回原文重新定位。

## 第08轮

**第08轮｜学生代理（AI 模拟）**

还有一种情况是论文根本没报告该条件下的 BER。如果检索不到，怎么区分「真没有」和「我们漏搜了」？我不想把这两种拒答都当成同一个好结果。数据里怎么造这个缺项，评分时又怎么区分？

**第08轮｜研究助手（AI）**

保留同一篇论文的实验条件锚点，但在生成真缺样本时不创建该 run 的 BER 记录。同篇仍可有其他 run 的 BER，所以 top-1 仍可能给错值。评分用与策略隔离的合成真值，把真缺时拒答计为合理拒答，把有真值时拒答计为未覆盖。运行时只观察到「未取得通过归属检验的证据」，不能仅凭 miss 断言作者没报告。除非有完整可靠的源索引能证明缺项，对外可说「未核实此实验的 BER」，不要说「论文没有测 BER」。同时报可答样本上的正确覆盖、全部请求上的错误提交以及真缺样本上的拒答。

## 第09轮

**第09轮｜学生代理（AI 模拟）**

刚才一直说「同一次实验」，可现实里距离和调制一样，也可能有不同接收功率、不同水体，甚至同一次实验报告了纠错前和纠错后两种 BER。这里实验键究竟是谁给的？我们把条件解析当作已知，会省掉哪一部分困难？请写出一个原型不该直接回答的问法。

**第09轮｜研究助手（AI）**

实验里 `(paper_id, run_id)` 由合成数据生成器赋值，每个问句有已知目标 `Condition`，六种方法都收到同样的结构化锚点。它省掉了自然语言到论文与实验的定位、条件归一、重复组的消歧以及指标口径选择。线上应尽量保持作者原有实验编号或稳定源行定位，没有可靠共同键时不能从距离和调制硬凑。比如「论文 P 的 10 米 OOK 的 BER 是多少？」若同时有同距离同调制的两种接收功率，或同一 run 有 pre-FEC 与 post-FEC 两个 BER，原型的单值契约不应直接答。需要澄清其条件、指标口径，或返回对照列并分别引用。另补充上一轮验证表的实现细节：模拟 `SourceCell` 保存真值数值供评分，但策略只比较 `cell.condition`，没有用该数值选候选或校数。真实部署可让校验端点只返回归属。

## 第10轮

**第10轮｜学生代理（AI 模拟）**

补一个会绕过「配对正确」的情况：源行确实对应这一 run，BER 却少抄了一个零，或把小于某个阈值抄成准确值。咱们的验证能抓住哪种？如果要做面向真实论文的下一步，最小需要从源里再核对哪些东西？

**第10轮｜研究助手（AI）**

当前实现进一步比较 `(原表条件, 原表值)` 与 `(目标条件, 候选值)`，因此候选 BER 少写一个零，且源表仍正确，就会因数值字符串不匹配而拒答。这修正了先前讨论中只验归属的最小设计。原型的数值格式是统一的，例如 `2.5e-5`。真实源表若有 `BER < 2.5×10⁻⁵`，需要把比较符号、有效位、标度、单位或无量纲语义一起结构化。把小于号吃掉若发生在索引链路而独立源保留原意，可以检出。两条解析链都丢了小于号便无法发现。最小核对原行定位、指标名称与 pre/post-FEC 口径、数值及限定符。还应区分零错误观测与证明 BER 为零，若原文报告统计范围则一并保留。

## 第11轮

**第11轮｜学生代理（AI 模拟）**

如果我把 top-k 从 2 改大，漏搜是不是自然就没了？实验怎么让我们看见 k 的作用，又不会把只在结果出来后挑的一档说成最优？还有，六种方法看到的是不是同一篇、同一批请求、同一份错标？

**第11轮｜研究助手（AI）**

加大 k 能挽回被排名截断的候选，不能恢复缺失键，也不能纠正同篇被交换的键。用预定的 `k∈{1,2,3,4}` 分别报告正确、错配、拒答、回传片段数量和补查调用次数。把 `k=2` 当便于阅读的主展示点，不称最优。程序对每个合成论文先固定条件与源行，再在每个污染场景生成一份索引视图，所有策略和 k 都复用相同论文、条件锚点和污染位置。各方法收到的候选窗口不同，但窗口基于同一排序；直接键查不消费 BM25 候选。主场景就是配对试验，不能把同一条件在不同 k 或方法下的输出算成独立请求。

## 第12轮

**第12轮｜学生代理（AI 模拟）**

等一下，条件已经给了结构化 run 键，为什么还要先 BM25，再用同一个键补查？这是不是有点绕？我要有一个「直接按键查，然后同样验原行」的强对照。它在什么场景下应该更合适，先搜索这一跳还有没有可能省东西？

**第12轮｜研究助手（AI）**

已经加入 `direct_verified`。它不取 BM25 候选，直接给同一键索引一次查询，有唯一片段再做同样的源行检查。在已知可靠锚点、查询便宜、只需一个 BER 的条件下，这是更直接的方案。先搜仍可能适合排序结果本来就已为其他问答拿到、专用键索引调用另有远程成本，或还需用候选段落做解释的场景。对于这个受控实验，最多能对照回传片段数和显式键查次数，各有一个单位，不能自行按同一单位相加并说更快。若日后需要证明搜索前置价值，要把候选是否已在手、键服务响应开销和端到端延迟都测出来。

## 第13轮

**第13轮｜学生代理（AI 模拟）**

那我想把成本记得更清楚。BM25 给了两个片段，是回传了两个，还是只扫描了两个？还有一次查源行，跟一次按键查 BER 是同一种读吗？请定义三个能从代码复查的计数，再说清为什么这些计数不能直接当成真实时延。

**第13轮｜研究助手（AI）**

`candidate_rows` 是交给配对流程的 BER 片段数，包含 top-k 或全量窗口和按键调用返回的片段。空键查也会发出一次调用，但增加 0 个片段。`lookup_calls` 记录按复合键显式查 BER 索引的次数，每个请求为 0 或 1，直接键查固定为 1。`source_reads` 是在选出唯一候选后读取独立源行的次数，读到不匹配也计一次。三种单位分别是片段、键服务查找、源表查找。模拟的 BM25 实际在进策略之前把同篇全体都打分，候选数不计排序的扫描、打分或建索引成本。物理时延还取决于这些步骤能否并行、网络位置、缓存和每条记录大小，所以不能从三列直接换算毫秒。

## 第14轮

**第14轮｜学生代理（AI 模拟）**

如果系统一律说「我不知道」，错配率也是零。实验的表能不能让读者一眼看出它究竟答对、答错，还是没答？请把每个分母说清楚，尤其是「覆盖率」这个词，我怕被误读成正确率。

**第14轮｜研究助手（AI）**

对每个方法用同一批请求数 `N` 作主分母。`correct` 表示源行与 BER 都匹配，`wrong_pair` 是提交的源行或 BER 有一项不匹配，`abstain` 是未交付值，三项计数和为 `N`。代码 `coverage_pct=(correct+wrong_pair)/N` 只衡量提交比例，答一切的策略也可达 100%；把它标作「作答覆盖率」。另列 `correct/N_answerable` 作为可答样本正确覆盖，`answerable_abstain` 显示有真值却未作答的量。总拒答减去这项就是无真值时的拒答。零错配只有和正确数、误拒数、真缺处置共同出现才可评估。若有用也可另外列已交付答案正确比例 `correct/(correct+wrong_pair)`，但它不能取代共同分母上的结果。

## 第15轮

**第15轮｜学生代理（AI 模拟）**

我们把看表的方法也先说定。干净键用哪两种策略对照补查收益，互换键用哪些策略对照复核收益？如果两种流程各有一个指标更好，应该怎么写才不会硬选一个「最优」？另外，设计讨论跟实现是并行的，别把这个顺序说成正式预注册。

**第15轮｜研究助手（AI）**

干净键用 `topk_join` 对同 k 的 `targeted`，差异来自缺匹配后增加一次定向补查。再用 `full_join` 校验干净键下能否恢复相同覆盖，并列可见片段数。互换键用 `targeted` 对候选选择完全相同的 `verified`，看同一条错误值是否转为拒答，同时检查原有正确配对是否保留。最后将 `verified` 与 `direct_verified` 分列可见 BER 片段、显式键查和源表查。单位不同或约束不明时只报取舍，不硬挑最优。提交材料可按设计后读结果组织，但如实说明实现、讨论与修订并行，且 k 网格及展示口径并未外部预注册。

## 第16轮

**第16轮｜学生代理（AI 模拟）**

我们看实跑。`run.json` 的样例里，`rowA` 和 `rowB` 都是 `2.5e-5`。独立取 top-1 报了 `rowB`，却没答对；补查返回 `rowA`。能按这个例子一步步讲一下 top-1、按键补查和源行校验到底看见了什么吗？我想在报告里用它解释为什么只检查数字会漏掉问题。

**第16轮｜研究助手（AI）**
